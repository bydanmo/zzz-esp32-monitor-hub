# 使用与常见问题

## 第一次启动

使用 Node.js 22.21+，在完整解压后的项目根目录执行 `npm ci` 和 `npm run build`。手动 `npm start` 在当前终端运行；Windows `tools/windows/start-monitor.cmd` 后台运行，`tools/windows/stop-monitor.cmd` 只停止启动器登记的进程。

`setup.cmd` 适合首次使用；后续启动器按源码与资源修改时间决定是否重新构建。运行状态和日志在 `.runtime/`，个人数据在 `apps/hub/data/`，均不提交。

重复启动会复用本启动器登记且身份匹配的现有进程。若 HTTP 健康检查暂时失败，明确警告并保留进程，不因一次超时自动杀掉它；可查看日志或手动停止再启动。构建产物有更新时仍会重启以加载新版本。

## 没有硬件

默认监控运行 Hub 的电脑，0 台设备是正常状态。3D 屏幕是预览，不代表存在一块实际 ESP32。温度等不支持的传感器显示原因，不注入随机值。

演示入口 `/?mode=demo` 使用本地示例，始终显示演示标记；不连接真实 WebSocket，不读取或写入真实 Hub 配置。屏幕编辑可探索本地草稿，应用不可用；考试目标写入会被拒绝。要设置真实目标，请返回实时模式。

## 设备连接

默认 Hub 仅监听本机。局域网使用时设置 `.env` 中 `HUB_HOST=0.0.0.0`，配置 Wi-Fi 和电脑局域网地址，确认防火墙与网络。当前无登录鉴权，只在可信本机／局域网使用，不直接映射公网。

网页外观与设备配置分别管理。换网页主题不会自动刷写设备；“保存到 Hub”“已推送”“设备已应用”是不同状态。

## 启动失败

- 找不到 node/npm：安装正确版本并重新打开终端；可先运行 `node --version`。
- 依赖缺失或版本异常：使用锁文件执行 `npm ci`，然后重新构建。
- 页面只有空白或旧样式：确认构建成功，刷新页面，检查浏览器控制台和 Hub 日志。
- 端口已占用：更换 `.env` 的 HUB_PORT，或终止自己启动的旧进程。启动器不会强杀不属于它的进程。
- 没有温度/GPU 数据：查看数据源页面；可选配置兼容的本地硬件监控服务，具体支持取决于电脑。
- 3D 不可用：使用平面预览。WebGL 初始化失败或上下文丢失有回退。
- 需要减少动态：使用简化动效、暂停背景和固定视角；动态数据仍更新。

## 文档范围

首版验证 Windows；macOS/Linux 不作已验证承诺。独立演示不是额外的后端服务，也不需要 GPU／ESP32／TF 卡。历史研究原图、私人媒体和完整厂商包未随仓库分发。
