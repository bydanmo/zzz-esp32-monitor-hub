# 素材库与器物生产规范

目标：把参考图、原创母版、平台导出和实际使用位置串起来，让美术资产可继续制作、可换主题、可复用、可恢复。

## 2. 入库与挑选

原件只读保存；转换、裁切、压缩和生成派生物另存。先记录文件名、尺寸、帧数、时长、SHA-256、来源和作者，再分用途。用内容哈希去重，重复文件保留来源关系；不默认删除用户源文件。

每个任务优先选一张构图参考、一张组件参考、一张器物／材质参考；有动作需求再加入录屏或视频。参考板附一句“本次学习什么”。例如：

| 任务 | 第一组参考 | 提炼目标 |
| --- | --- | --- |
| 设备总览／详情 | REF-U02、REF-U11、R199 | 主体与属性面、屏框厚度、屏中屏 |
| 高密度编辑 | REF-U05、REF-U08、R093 | 工作台层次、列表、资源与参数 |
| 表单与连接 | R055、R086、REF-U15 | 纸面秩序、身份索引、列表选择 |
| 媒体操作 | R075、R117、REF-U14 | 控制器外壳、圆盘／卡匣、真实按键 |
| 主题／封面 | R107、R111、R128、R189、R236 | 不同印刷色面与中性器物的关系 |
| 背景与动效 | REF-U01—U06 的底图、Creamfields | 大字分层、裁切、重复、机械节奏 |

研究图可以展示原作的结构；生产件优先建立原创轮廓、排版和贴花。内部原型曾接入五张参考封面；公开首版已替换为原创 SVG，见 web/public/art/original/sources.json。“已接入私用项目”与“已核验公开分发条件”分别记录。

## 3. 一个母版，两条表现线

### 3.1 设定和造型

先写物件的用途、使用者、摆放环境、操作方式和连接方式。再做正面、侧面、背面或等效结构图，说明显示区、外壳、屏框、控制件、接口、通风、底脚和贴花。

每个采用的部件标注：功能、是否能动、动作范围、是否对应真实硬件、是否只是展示元素。插槽应有入口与厚度，旋钮应有轴与限位逻辑，标签应附着于表面，字体不能穿过拼缝。

当前终端的身份锚点：3:2 实际显示区、CRT 深框、厚机壳、实体控制、录像机底座与卡匣关系。允许机壳换色与视角改变，身份锚点保持一致。

### 3.2 双表现规格

| 内容 | 操作图形版 | 展示精细版 |
| --- | --- | --- |
| 几何／剪影 | 减少小分件，保留关键厚度和轮廓 | 细化相同部件，保留装配与接触关系 |
| 明暗 | 少量清楚的明暗组，读数和操作优先 | 可用更细的光照、遮挡和反射 |
| 材料 | 用色块、边缘、有限纹理识别 | 增加可控粗糙度、玻璃和微表面 |
| 贴花 | 保留功能、品牌和主要索引 | 同一贴花母版，可增加合理小铭文 |
| 动态 | 选中、状态、有限部件动作 | 摄像机与主体联动，必要时细节展示 |
| 验收 | 实际控件尺寸能读能点 | 放大后结构、文字和材质仍成立 |

不能把 AI 生成概念 PNG 称作可编辑模型，也不能把正面渲染图当成已完成背面结构。现有程序化终端和 GLB 属于已建立的原创概念母版；新的产品级精修仍需对应验收。

### 3.3 材料、贴花与灯光

先定材料分区，再做纹理。粗糙度、反射、轮廓光服务物件识别，避免整台设备呈相同塑料质感。贴花单独成层，保留无贴花版本和字体依赖。

常规展示视图先用稳定主光、少量补光与轮廓光，检查暗部是否仍可见。主题换色时，灯光不能把关键部件全部染成同色；屏幕亮度不能吞掉机壳边缘。

使用痕迹来自手接触、插拔、落脚与擦拭位置；用户选择的是维护良好的在用品。大面积锈蚀、均匀噪点、破损标签不是默认风格。

## 5. 命名、版本与登记

稳定资产 ID 与文件路径分离。文件建议使用 ASCII 小写短横线，如 `terminal-main-operational-mixed-front-idle-v001.webp`。不要用“最终版2”“新新修改”表达版本。

登记字段分组如下；没有证据时使用 `null` 或明确状态，不伪填已通过：

| 分组 | 字段 |
| --- | --- |
| 身份 | asset_id、名称、用途、版本、master_id、derived_ids |
| 来源 | source_kind、source_path／url、作者、取得日期、SHA-256 |
| 使用条件 | rights_status、许可记录路径、署名、修改／分发条件、核验日期 |
| 设计 | reference_ids、观察、转译、不可变特征、变体与确认状态 |
| 母版 | 可编辑路径、工具版本、单位、坐标、枢轴、命名部件与依赖 |
| 导出 | 平台、格式、尺寸、字节数、色彩空间、透明／遮罩、编码、参数 |
| 动态 | 时长、帧率、真实源帧数、循环、状态、中断和回退 |
| 运行 | 加载、解码、内存、传输、测量设备、使用落点 |
| 验收 | source_review、visual_review、interaction_review、platform_review、public_release_status |

状态分开记录：`research`、`candidate`、`prototype`、`integrated`、`visually_confirmed`、`platform_verified`、`retired`。同一资产可已接入但尚未精修或公开发布；一个 true 不能替代所有维度。

## 6. 导出与性能规格

### 6.1 Web／软件

静态大图优先按实际显示尺寸导出；透明资产检查白边和预乘；图标／几何件适合矢量或代码时保持可编辑。照片和已绘制器物使用适合的位图，不用大量切碎 DOM 复刻。

三维资产交付命名节点、材质、贴图、枢轴、单位、包围盒与基准视角。GLB 是运行导出，必须能找到母版；实时屏幕、相机、灯光与交互若在网页单独实现，交付说明要列出。

当前概念终端约 23,062 三角形、89 节点、13 材质，属于已存在的基线，而非所有新对象的预算上限。Web 运行当前采用延迟加载、DPR 上限、按需绘制、离屏与隐藏暂停；新增资产按目标设备重新测量首载、内存和互动表现。

### 6.2 ESP32／嵌入式

先分别计算：资源存储、运行内存、解码缓冲、DMA 内部内存和传输量。显示分辨率、总线、缓存与源素材帧率共同决定方案，不能只填“目标 30 FPS”。

当前设备的已验证案例：

- 画布 480×320；RGB565 全屏单帧为 307,200 字节。
- CRT 静态房间铺满画布，动态窗口 198×150，16:9 内容在窗口内保持比例；单帧 59,400 字节。
- 120 帧窗口数据 7,128,000 字节，加背景共 7,435,200 字节；需另考虑系统和传输内存。
- PSRAM 局部播放已记录约 30 FPS 的实机证据；读卡直接逐帧的旧方案明显更慢。此结果限定于该设备与该窗口，不能推广到任意全屏素材。
- 监控 UI 用局部失效与原生绘制；离屏刷新像素计数反映软件工作量，不等于物理显示帧率。

同一素材先做全屏与局部对照，按实际可读性与测量选择。可以通过静态场景＋动态窗口保留完整器物氛围，降低传输量。

### 6.3 视频与 GIF

先查原始真实帧间隔，再裁出真正动态区域。现有 14 GIF 多为长宣传图中的局部演示，大多约 15 源 FPS；编码成 30 FPS 不会增加真实动作样本。

制作循环时检查首尾姿态、速度、纹理和光照；必须完整播放数轮。裁切、遮罩、缩放与窗口坐标写入导出记录。CRT 场景中“外层铺满”和“内层保留视频比例”分别验证，避免拉伸屏框或器物。

## 7. 来源与交付状态

参考学习、项目内使用、修改、公开分发分别登记。公开下载页面需要记录具体单项和条件；图上的品牌、角色与贴图依赖独立核对。先保留来源证据，再决定生产方式。

外部模型导入后重新检查比例、材质、贴图路径、隐藏对象和字体；不能因扩展名是 GLB 就视为可用。生成式图像记录输入、版本与用途，它可以帮助概念探索，但不能替代未制作的可编辑母版。

原始资源不整体复制进运行包。运行包只包含当前页面真正使用的导出文件、依赖和来源索引；大原件和研究缩略图留在资料层。
