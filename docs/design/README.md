# 我们的绝区零风格设计流程 v1.0

更新：2026-10-24。适用：网页、桌面软件、设备操作界面、嵌入式屏幕，以及与界面关联的三维器物。

这是本项目共同形成的工作方法：以《绝区零》的功能界面、印刷设计和生活器物为研究依据，形成自己的布局、品牌、组件、资产与交互。v1.0 表示流程可复用；具体页面、全部视觉参数和后续资产范围仍由任务评审决定。

## 从这里开始

| 要做的事 | 读什么 | 交付什么 |
| --- | --- | --- |
| 开始一个新页面或新项目 | 本文第 1—4 节 | 任务简报、参考组、灰阶构图、有限试样 |
| 判断画面是否有我们要的气质 | [视觉语法](visual-language.md) | 形状、排版、材质、配色和动作的具体判断 |
| 制作终端、音响、鼠标或素材 | [素材与器物生产](asset-production.md) | 母版、双表现、平台导出和来源清单 |
| 把工作交给另一个 Agent | [Agent 任务合同](agent-contract.md) | 可复制的完整输入与验收要求 |
| 找回讨论、图片与当前状态 | [决策与证据](decisions-and-evidence.md) | 决策来源、确认程度和历史边界 |
| 程序查找参考图 | 参考路由表 | 稳定 ID、路径、哈希和对应设计任务 |

新任务的最小输入包：本文件、视觉语法、Agent 任务合同、3—6 个相关参考，以及业务和平台约束。需要器物或素材时追加资产生产文档。不要一次塞入所有图片，让 Agent 自行猜重点。

## 1. 我们已经确定的核心

**用复古电器与街头印刷的组织方式，承载真实、可操作、可长期阅读的软件功能。**

| 维度 | 已确定的方向 |
| --- | --- |
| 总体气质 | Retro-Pop、街头机能、工业印刷、高饱和二次元；强调关系与秩序 |
| 主要参照 | 游戏菜单、角色属性、背包、设置等功能界面；辅以档案、店铺、展陈、器物与周边 |
| 主视觉 | 设备本身承担主视觉；当前原创终端从 CRT／录像机出发，保留 3:2 显示区 |
| 器物身份 | 厚机壳、深屏框、可解释的实体控制件；在用且维护良好，少量合理使用痕迹 |
| 双表现 | 同一母版的操作图形版与展示精细版，保持轮廓、部件、贴花身份一致 |
| 主题 | 可切换；网页主题、机壳配色、状态色分别管理 |
| 文案 | 中文真实功能名为主；少量有依据的原创品牌、型号与副标题 |
| 动态 | 大字背景、明确选中、短促面板进退、主体与视角联动；可暂停、可简化 |
| 功能器物 | 媒体、输入、连接等模块各有合理器物表达；是否出现取决于真实能力 |
| 评审方法 | 同页、同数据、同状态的 A/B 比较器物化程度；新页面可沿用已通过的组件家族 |
| 小屏 | 另做 480×320 构图和刷新设计，建立菜单、监控、媒体之间的切换关系 |

两种器物化程度仍是选择机制，不把某一稿永久定为所有页面的唯一答案。首页可强调物件；高密度编辑页可以让工具布局占主导。

## 2. 完整流程与关口

流程顺序：**澄清任务 → 整理证据 → 提炼规则 → 构图 → 同页试样 → 母版与组件 → 动效 → 平台实现 → 实际验收 → 版本归档。**

每个关口只解决会改变下一步成本的判断。用户已明确认可的方向直接继承；日常实现与可逆修正继续推进。新的主体轮廓、大批资产生产、产品功能改变等再提供具体对照给用户选择。

| 阶段 | 必做工作 | 产物 | 进入下一步的条件 |
| --- | --- | --- | --- |
| G0 任务定义 | 确定用户、任务、真实字段、平台、输入方式、范围和现有资产 | 一页任务简报、状态表 | 主要内容与不可变项清楚；关键未知已提出 |
| G1 参考研究 | 为构图、组件、器物、动态各选少量相关证据；标明排除区域 | 参考板与“观察→规则→落点”表 | 能说明每个参考具体解决什么问题 |
| G2 灰阶构图 | 先安排主体、主读数、信息面、导航、留白和操作次序 | 同业务的灰阶版、窄屏版 | 无纹理时仍有焦点、层级与可读性 |
| G3 风格试样 | 一页 A/B 器物化对照；主题、字形、背景、器物材质同时可观察 | 静帧、短交互录屏、简化版 | 选定本次方案或指出明确差异；记录确认程度 |
| G4 生产规格 | 冻结本轮对象、组件、状态、变体、输出、预算与回退 | 资产矩阵与组件状态表 | 生产范围有限且有母版关系，依赖明确 |
| G5 制作 | 母版、排版、贴花、双表现、颜色变体、动作分层 | 可编辑源与导出物 | 各表现仍为同一物件，资产可追溯 |
| G6 平台实现 | 网页、软件与设备分别适配；保留真实状态和输入能力 | 可运行页面／设备版本 | 主要流程可执行，异常状态有明确落点 |
| G7 验收 | 视觉、业务、交互、无障碍、性能、素材来源分别检查 | 截图、录屏、日志、测量、用户反馈 | 硬性项全部通过；审美确认与技术通过分别记载 |
| G8 归档 | 写版本差异、规则变化、资产状态、恢复步骤 | 版本记录、参考路由、任务总结 | 下一个 Agent 能找到当前入口和正确母版 |

### 2.1 G0：先把功能和未知写清楚

任务简报至少回答：谁使用、使用频率、首要动作、必须读到的值、输入方式、目标画布、运行环境、已有界面、现有数据源、允许修改的范围。

把未知分成三类：

- **会改变方向**：主体母题、画面重点、器物化程度、是否需要新功能。先沟通；不能用随机发挥代替答案。
- **可以试样验证**：主题色、字重、圆角、纹理强度、动作时长。给有限对照，并标为候选参数。
- **实现细节**：组件拆分、局部裁切、缓存与编码。由执行者在约束内完成并提交证据。

先处理设计任务，不把购买、建模、编程、刷机混成一个不可评审的大步骤。每轮完成一个可运行、可观察、可恢复的增量。

### 2.2 G1：参考板必须有推理链

参考板按任务选图，而非按“好看”堆图。每条研究记录采用以下结构：

| 证据 | 观察 | 我们的规则 | 本次应用 | 边界 |
| --- | --- | --- | --- | --- |
| REF-U02 | 左侧主体，右侧身份与双列属性，顶部对象与底部功能分开 | 主体、信息和两级导航有独立位置 | 设备详情首页 | 原图比例是观察，不是 480×320 的缩放模板 |
| R055 | 浅纸、黑标题条、字段下划线 | 表单采用纸面秩序 | 连接或目标设置 | 不照搬原文、印章和个人字段 |
| R075 | 机壳、凹槽、网面与旋钮分层 | 媒体控制器拥有统一外壳 | 播放模块 | 外观不能暗示不存在的音频能力 |
| Creamfields | 高饱和字带与暗底重复图形形成运动焦点 | 背景采用分层字带与受控局部动态 | 页面氛围与设备局部播放 | 宣传动画节奏另行适配长期监控 |

静帧证明轮廓、材质、布局；录屏证明触发、时序、路径和中断。拿不到连续影像时，动作参数写为我们的试样选择。

### 2.3 G2：先做无纹理、无动画的版面

按这个顺序检查：主任务 → 主读数／主体 → 必要状态 → 常用操作 → 次级设置 → 环境图形。

一个视图先建立一个主要焦点。倒计时与设备可形成主次配合；多个同尺寸、同颜色、同边框的卡片会抹平层级。深色信息槽、器物机壳、浅纸表单可以并存，但各有职责。

选用的布局家族：

- **主体档案型**：设备与身份、属性、常用动作并置，适合总览和详情。
- **资源工作台型**：资源列表、预览、参数、操作组成稳定工作区，适合编辑与主题库。
- **媒体展陈型**：物件或画面占中心，少量稳定播放控件，适合媒体查看。
- **纸面设置型**：清楚标题、字段、说明与保存反馈，适合连接和目标编辑。
- **紧凑监控型**：主数字＋少量次级指标＋底部导航，适合设备。

桌面“主体约半幅”等参考比例只用于起稿。先检查实际内容、手机重排与焦点位置，再决定当前布局。

### 2.4 G3：同页对照，避免靠内容差异取胜

A 稿保留清楚的软件结构，关键按钮、导航和主视觉有实体感；B 稿增加机壳、插槽、物理控制和模块轮廓。两稿统一业务内容、数据、状态、视口、设备角度、主题与操作路径。

至少提交：正常、当前选中、异常、窄屏、简化动效五类画面；一个 10—20 秒以内的主要流程演示。新主题只选一个稳定页面试色，避免六个不同页面造成误判。

评审按次序：构图与阅读 → 字体与背景 → 组件家族 → 器物可信度 → 动态节奏 → 长时间使用。记录用户具体意见，如“缺少大字背景”“文字重合”“上方留白过大”，并指向修正区域。

### 2.5 G4—G6：先母版，再派生，再平台适配

每个器物先有用途、剪影、部件、材质和印刷设定。操作版与展示版共享同一身份；网页模型、静态图和小屏图形是派生资产。一个页面上的螺钉、网面、旋钮不能各来自不同、不相干的产品。

先做“常规尺寸＋默认状态”的组件，再完成选中、焦点、按下、忙碌、禁用和错误。之后才扩展主题和素材变体，避免成倍返工。

使用滚动 3D 时先固定正面、侧面、背面几个有功能意义的视角，再定义滚动映射；数据阅读区和键盘焦点稳定。小屏先验证静态字形和触摸，再加局部运动与缓存。

### 2.6 G7：用实际画面结束一轮

网页使用真实浏览器检查桌面、390、320 像素宽度，检查内容溢出、焦点、触摸、主题与动效控制。软件按其窗口与输入设备补充。ESP32 用真实字体在 480×320 渲染，并以物理屏幕、触摸和串口数据补全。

测试图上的数据明确标记为夹具；实际接口与设备状态另行核对。检查必须能回答“画面真的显示了什么”“用户真的能做什么”“刷新和内存到底花了多少”。

## 3. 每轮统一交付包

| 文件／内容 | 最小要求 |
| --- | --- |
| 任务简报 | 目标、场景、功能、平台、范围、未知、继承规则 |
| 参考板 | 少量编号参考、观察、转译、排除区、可用范围 |
| 构图与对照 | 正常画面、至少一个窄屏、必要时同页 A/B |
| 组件表 | 每类组件职责、形状家族、文字层级、状态与点击范围 |
| 动效表 | 触发、对象、路径、时长、层序、中断、暂停、简化与回退 |
| 资产表 | 母版、派生、来源、状态、规格、依赖和当前落点 |
| 实现与证据 | 实际截图、可运行版本、针对性检查、性能观察 |
| 差异与恢复 | 改了什么、为何改变、用户确认内容、未验证部分、恢复方法 |

文档可合并，但这些信息不能遗漏。先保留一份当前入口，再链接历史记录；不要把十份“最终版”当成当前规范。

## 4. 验收标准

### 4.1 必须通过的项目

- [ ] 主任务与最重要数值在第一眼可定位；数字、单位、日期、标题不重合。
- [ ] 当前项同时有形状／边界和文字差异；焦点、禁用和选中可区分。
- [ ] 正文在不透明阅读面上；装饰不阻挡点击、不遮挡错误和状态。
- [ ] 中文缺字、冒号、百分号、负号、长数字、未知值都检查过。
- [ ] 状态来源真实；在线、数据新鲜、已发送、已应用分别表达。
- [ ] 简化与暂停有效；快速切换、中断和返回落点明确。
- [ ] 主题切换保持状态含义；机壳换色保持部件身份。
- [ ] 目标平台实际运行；主机渲染、视频素材 FPS 与设备显示 FPS 分开记录。
- [ ] 使用的资产有来源与状态；概念图、模型、制造图明确区分。
- [ ] 本轮变更有备份和可执行的恢复路径。

### 4.2 审美复核的六个问题

1. 去掉发光，轮廓、比例和字体仍有识别度吗？
2. 去掉纹理，功能和主次仍清楚吗？
3. 把角色换成设备，构图仍成立吗？
4. 每个旋钮、格栅、插槽都能解释用途吗？
5. 连续使用十分钟，是否被装饰打断阅读？
6. 换主题或换平台，是否仍能认出同一套产品？

硬性项通过后，再按构图、文字、组件、器物、色彩、动态逐项做“通过／需调整”的评审。技术测试通过不能自动记为审美确认。

## 5. 文档与版本规则

新流程是当前工作入口；`art-production-spec.md`、`asset-plan.json` 等 2026-10-22 文件保留为当时的规格与候选计划，不作为当前资产完成状态。当前完成程度以[状态表](decisions-and-evidence.md)和对应实现、验收记录为准。

变更分类：新增规范版本用于流程和视觉语法改变；页面版本用于布局与交互改变；资产版本用于母版和导出改变。参考图维持 ID 与内容哈希，新增图追加登记，不把旧 ID 改成另一张图。

长期项目记忆保留：用户已确认的方向、当前规范入口、参考与母版位置、验收方法。端口、在线数、固件哈希和某次帧率留在对应验收记录，使用前重新检查。
