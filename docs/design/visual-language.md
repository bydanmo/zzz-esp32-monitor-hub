# 我们的视觉语法

配合[完整流程](README.md)使用。下面将参考观察、项目选择与制作起点分开；尺寸和时长是我们的工程参数，不代表原作官方规范。

## 1. 气质从哪些关系产生

| 方向 | 在画面里的具体表达 | 常见偏离 |
| --- | --- | --- |
| 复古潮流 | 磁带、收音机、CRT、档案、纸刊的组织方式；窄体大字、网点和印刷色块 | 给普通后台贴一张复古壁纸 |
| 街头机能 | 铭牌、型号、分件、运输／检修标记、紧凑控制件、模块化关系 | 无用途的英文和过多警告贴纸 |
| 工业警告 | 黑色边界、醒目实色、斜纹、索引、插槽与机械节奏 | 所有卡片都黄黑相间，层级消失 |
| 高饱和二次元 | 选择性夸张轮廓、清楚明暗分组、饱和焦点、图形化材料和贴花 | 只加黑描边、全屏霓虹或过度卡通化 |

画面应同时有大、中、小三个尺度：大字与主体建立势能，中型容器组织功能，小型铭文、纹理和五金说明材料。三种尺度都要服务于同一个版面。

## 2. 构图与比例

### 2.1 主体档案型

参考 REF-U02、U03、U04、U06。桌面先以主体约半幅、信息面约四成作为草图起点，再按真实内容调整。主体可越出框；信息区域拥有稳定边界；对象切换和功能导航保持独立。

我们的主体是终端，身份信息是设备名称／连接／能力，属性是 CPU、内存、目标等真实字段。主体特写不能压缩到使用户找不到功能。手机把主体与数据重排成顺序阅读，不缩小整张桌面画布。

### 2.2 工作台型

参考 REF-U05、U08、R055、R086。资源、预览、属性、动作形成固定分区。高密度页面允许减少大物件，让列表、字段和当前选择占主导。每个数据项不必单独拥有厚机壳；一个工作台壳体可组织多个凹槽。

### 2.3 紧凑监控型

480×320 的信息次序为主读数、少量次指标、导航；小型在线点承担全局提示，细节通过点击展开。当前总览约为左侧 288px 票面、右侧 156px 指标列，内容区 456×236；这是本项目已实现布局，其他设备按内容重新排。

单位作为独立文字，与数字按可见字形底部对齐。跨越 999→1000、100% 和缺失状态时检查宽度；长数值使用紧凑字形或明确上限，不把单位挤出边界。

## 3. 背景是印刷版面

按后到前组织以下层次，具体页面可以省略部分层：

| 层 | 内容 | 约束 |
| --- | --- | --- |
| B0 底材 | 墨黑、灰蓝、纸面等主题底色 | 先确定明暗关系，底材不参与点击 |
| B1 大字 | 超大压缩字、重复字带、局部裁切 | 词汇与产品／模块有关，允许被主体大面积遮挡 |
| B2 结构 | 胶片、斜带、网点、圆盘、细标签 | 形成方向、节奏、材料，避免每种同时抢眼 |
| B3 舞台 | 地台、设备阴影、局部色带、环境画面 | 托住物件；与真实界面阅读面分开 |
| F0 外壳 | 工作台、面板框、手册、仪表壳 | 轮廓与内嵌关系清楚 |
| F1 阅读面 | 深色槽、票券、纸张、屏幕 | 主要内容落在稳定、足够不透明的平面 |
| F2 交互 | 按钮、选择、焦点、反馈 | 状态优先于纹理；装饰不穿越此层 |

大字可以倾斜、窄化、跨边界；正文保持正向。背景可以比内容更大、更粗、更密，但对比度低于当前焦点。不要通过全局透明度把状态与功能也一起压暗。

制作大字底稿时先检查静帧：是否有完整字带、方向、遮挡和裁切关系。之后加入错速移动；每条带记录字高、字距、重复间距、路径和循环接缝。不能把一个短词无间距铺满屏幕就视为完成。

网页可用多层背景、错速长周期；设备优先少量可见印刷字和小范围纹样。当前总览点阵扫描与斜纹输送是设备转译，不是照搬宣传片整屏运动。

## 4. 组件家族与厚度

### 4.1 五层结构

外轮廓负责识别；边肉负责厚度；凹槽负责内容归属；微高光说明表面方向；选中层说明当前状态。按组件需要取舍，不要求所有件都有五层。

黑描边要形成结构，不将每条分隔线都加粗。常规网页从 2—3 CSS px 的主边界试起，细分隔线更轻；小屏直接观察真实像素，不按设备像素比机械换算。

### 4.2 组件配方

| 组件 | 形状与材料 | 内容与状态 | 动作 |
| --- | --- | --- | --- |
| 主按钮 | 厚胶囊或短实体键、黑边、少量边缘高光 | 主动作文字为主体，主题色填充，按下和焦点独立 | 短按压、快速恢复；忙碌时保留尺寸与标签含义 |
| 次按钮 | 深色网面／橡胶键，低一档实色 | 与主按钮同家族，避免多个动作同时成为主色块 | 同一按压逻辑，强度可低一些 |
| 分段导航 | 深色轨道、主题色滑块或嵌件 | 当前项主题填充＋黑边＋文字差异；不可用项有语义 | 快速连续切换不排队、不累积位置 |
| 资源槽位 | 厚框与内凹缩略图窗，统一比例 | 可用、空、选中、不可用、错误分开 | 选中锁边、轻微位移；列表滚动保持可定位 |
| 数据仪表 | 中性外壳、深槽、主读数、单位、少量编码 | 数值和状态最清楚；曲线与刻度为辅助 | 数值驱动圆弧／条长，避免装饰伪造变化 |
| 票券读数 | 斜切纸面或标签、黑色标题／时间窗、点阵／斜纹 | 一处主要实色；大数字和单位留出独立区域 | 边缘纹样可动，文字与时间窗稳定 |
| 纸面表单 | 米灰纸、深标题条、下划线、有限印章／索引 | 字段、帮助、校验、保存反馈有清楚层级 | 展开或提交反馈短促；输入文字不倾斜 |
| 状态点／标签 | 小灯、标签或嵌入式指示器 | 颜色配合文字或可展开详情；在线和数据健康分开 | 可用于短暂确认，避免持续强闪 |
| 媒体控制器 | CRT／播放器壳、显示窗、实际控制键 | 播放、暂停、进度、错误与返回 | 受用户控制；离开视口停止无意义连续绘制 |
| 抽屉／弹层 | 有厚度的工作面、稳定关闭锚点 | 当前对象、内容与操作次序清楚 | 进入、返回、快速重入与取消都有落点 |

圆形仓位适合空间关系明确的模块；普通设置仍用列表和表单。斜切只用于选择、标签和局部构图，不强制全界面倾斜。命中区域可大于视觉轮廓，触摸与焦点必须检查。

## 5. 字体与文字

中文标题厚实紧凑；数字稳定且有足够辨识度；英文窄字与斜字用于环境、索引和短标签。长说明、错误、操作帮助优先正向阅读，不能依赖描边才看得清。

| 角色 | 当前实现或建议起点 | 要检查的细节 |
| --- | --- | --- |
| 背景大字 | 独立窄体／倾斜展示字，按构图裁切 | 可遮挡，不承载必需说明 |
| Web 主数字 | 当前约 78—114px；窄屏另有规则 | 长读数、百分号、负号、单位间距 |
| Web 分区标题 | 当前桌面 25px、窄屏 21px | 中文字重与混排基线 |
| Web 仪表数字 | 当前桌面 40px、窄屏 34px | 固定读数槽与缺失值 |
| Web 正文 | 建议先从 14—16px 起稿，按阅读密度调整 | 行距、对比度、输入与错误长文 |
| 设备标签 | 当前 16px 字库 | 真实字形、缺字、行盒与可见墨迹差异 |
| 设备数值 | 当前含 28／40／56px 数字与 84／112px 海报字体 | 以实际墨迹边界测量，不能只看字号 |
| 设备时分秒 | 当前 28px 数字字体，明确包含冒号 | `00:00:00`、`23:59:59`、`--:--:--` |

现有字体为项目加工的 Noto 子集，许可与派生文件另有记录。不要根据截图猜测具体商业字体，也不要因英文字好看而忽略中文。换字体是一项布局变更，需要重查基线、字宽和缺字。

可读性作为项目验收目标：普通正文先按 4.5:1、较大文字／关键图形按 3:1 检查，必要时提高；这不代表整个产品已经通过无障碍认证。状态不能只依赖颜色。

## 6. 颜色分成五套变量

1. 页面主题：画布、主色、次色、印刷字、面板。
2. 器物材料：机壳、深屏框、玻璃、塑料、金属、标签纸。
3. 交互：当前项、悬停、焦点、按下、禁用。
4. 业务状态：在线、连接中、失败、数据过期、未保存、已应用。
5. 数据系列：CPU、内存、温度等需要比较的系列。

颜色可以共享具体色值，但变量职责不能合并。把机壳从黑改白，不应把在线绿改为主题粉，也不应改变图表系列含义。

## 7. 器物与材质

原创 CRT／录像机终端是第一套母题。其关键身份是厚度、深屏框、实体控制、底座／卡匣与 3:2 屏幕；其他项目可以继承方法，按真实任务选择器物。

二次元化的制作次序：

1. 提取远看可识别的剪影，放大一两个功能特征。
2. 将外壳、屏框、控制件分成清楚的大形，确认主次尺寸。
3. 把明暗归并成少量稳定组，保留接触、转折和关键反射。
4. 用贴花、型号、色块、刻度说明身份与功能。
5. 按最终尺寸删去无效细节，再增加少量表面质感。

橡胶适合低反光、厚边与网面；塑料用大块颜色和柔和高光；金属保留窄高光和合理粗糙度；纸张用印刷与折边而非金属反射；玻璃有边缘反光但不持续扭曲正文。

磨损集中在触摸、插拔、底脚和握持边缘，整体干净。螺钉应在装配位置，风口应对应散热，喇叭网应说明用途；不能靠随机增加五金件表达“高级”。

精细展示版允许更完整的反射、灯光与细节；操作版减少细碎噪点，保留轮廓与材料线索。禁止把两种表现做成互不相干的两个物件。

## 8. 动作语言

动作承担四种任务：确认输入、解释层级、引导注意、形成环境节奏。先明确任务，再选位置、速度与时间。

| 动作 | 制作起点／现有实现 | 中断和简化规则 |
| --- | --- | --- |
| 按压／选择 | 建议 100—180ms，1—2px 或局部色面变化 | 连续输入覆盖旧动作，不排队 |
| 面板进退 | 建议 160—240ms，短距离，阅读面尽快可操作 | 返回有稳定落点；简化模式直接到位 |
| 数据过渡 | 真实值变化驱动，约数百毫秒内落稳 | 无效、缺失、过期不得伪造新变化 |
| 背景大字 | Web 当前常用 35—64s 错速循环；设备另做局部漂移 | 暂停／简化时静止，正文不跟随运动 |
| 机件运动 | 仅在表达功能或氛围时使用，如磁带卷轴 | 离开场景释放或停止，避免无意义常驻 |
| 3D 滚动 | 有限的正／侧／背视角映射，保留手动控制 | 暂停冻结；简化固定；异常回退平面 |
| 设备纹样 | 当前点阵与斜纹局部刷新，约 15 次/秒装饰节奏 | 简化时关闭，不让大数字跟随失效 |
| 设备进度光带 | 限定在真实填充内，周期约 2.2s | 离线、非 fresh、无值、零值时停止 |

每段动作还要填写：触发事件、源状态、目标状态、层序、运动路径、曲线、循环接缝、何时可操作、取消规则、失败回退、重入与离开视口策略。

宣传片可用强冲击，大多数功能界面应使用更克制的持续运动。避免整屏频闪、持续文字抖动、每秒切换主色和无法暂停的镜头。音效尚未形成已确认规范，新任务单独讨论。

## 9. 平台转译

| 关注点 | Web／软件 | ESP32／嵌入式 |
| --- | --- | --- |
| 布局 | 随窗口重排，可分区和滚动 | 固定画布重做，保留足够触摸面积 |
| 主体 | 交互 3D、预渲染或平面均可按预算选 | 静态场景、图形化器物与局部动态优先 |
| 文字 | 多字级，系统输入与键盘焦点 | 子集字库、可见墨迹、短文案与边界测量 |
| 动态 | 按需渲染，隐藏／离屏停止 | 小矩形失效、分块传输、缓存与实际帧率 |
| 材质 | 少量微表面和实时光照可用 | 用形状、色块、有限纹理表达 |
| 失败 | 平面图、错误提示、保留功能入口 | 稳定监控回退、资源校验、旧媒体保留 |

继承的是物件身份、信息层级和动作原因。平台预算不同，导出格式、帧数、材质与布局都可以不同。
