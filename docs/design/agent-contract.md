# 可直接交给 Agent 的任务合同

先读[流程](README.md)、[视觉语法](visual-language.md)，按任务追加[素材生产](asset-production.md)。以下内容是输入与输出约定；使用时按实际项目提供字段，不能猜造缺失业务。

## 1. 短版风格约束

```text
本项目继承绝区零的功能界面、街头印刷与复古器物设计方法。
总体气质：Retro-Pop、街头机能、工业警告、高饱和二次元。
先建立主体、主要读数、信息面与操作的层级，再增加纹理与动态。
大字背景有排版、裁切、遮挡和错速关系；正文保持稳定阅读。
组件使用黑色结构边界、中性机壳、深色内容槽和局部主题色选中。
页面可以使用票券、档案纸、卡匣与电器结构，但每种结构有真实功能。
同一器物母版输出操作图形版与展示精细版，保留身份与屏幕比例。
机壳颜色、页面主题、交互状态和业务状态分别管理。
中文真实功能名优先；品牌、型号和微文案要有依据。
动画解释操作与层级，持续背景低干扰；支持暂停、简化和失败回退。
Web、软件和嵌入式分别适配，不整体缩放桌面稿到小屏。
不虚构设备能力、在线状态、实时数据或已应用结果。
交付可运行结果、实际画面、对应测量与恢复说明。
```

短版约束只用于提醒，不能替代参考板、业务字段和验收要求。

## 2. 完整输入字段

| 字段 | 必须提供的内容 |
| --- | --- |
| 任务目标 | 一句话说明用户要完成什么，首要动作和阅读重点 |
| 平台与输入 | Web／软件／设备、画布、窗口、鼠标／键盘／触摸、运行环境 |
| 真实内容 | 字段、单位、来源、刷新方式、最大长度、缺失／错误／过期状态 |
| 当前基线 | 实际页面、截图、源文件、可复用组件和已确认决策 |
| 本轮范围 | 修改区域、可变项、不改项、新资产是否在范围内 |
| 参考包 | 3—6 个编号、每张学习目标、排除区域、动态证据 |
| 布局家族 | 主体档案、资源工作台、媒体展陈、纸面设置、紧凑监控之一或合理组合 |
| 风格规则 | 必须继承的轮廓、字形、主题、材质、背景、器物身份 |
| 动作合同 | 触发、源／目标状态、路径、时长、重入、中断、简化与回退 |
| 资产白名单 | 可直接使用的文件；参考件、概念件和生产件分别标明 |
| 预算 | 初载、运行内存、传输、刷新与目标设备；未知写明实测方式 |
| 验收 | 关键状态、视口、主要流程、截图／录屏、测量和用户判断点 |
| 交付 | 文档、可编辑源、运行文件、来源索引、差异与恢复 |

字段缺失时先从项目和现有材料查找。会改变方向的未知明确提出；其余在已授权范围内推进，并把试样参数写明。

## 3. 执行顺序

1. 用简短文字复述任务、继承的决策和关键未知，不重复询问已有答案。
2. 查当前实现与参考。提交“参考事实→本项目规则→本次落点”，不凭名称猜图。
3. 建立灰阶构图与阅读顺序。新主体／器物化深度需要选择时，制作同页对照。
4. 用最少组件建立真实功能骨架，检查正常、缺失、异常与处理中。
5. 实现形状、字体、主题、纹理和器物；来源资产按清单使用。
6. 加动作并处理取消、快速输入、隐藏、简化和失败回退。
7. 在目标平台运行，按本次变化执行有意义的检查，修正实际画面。
8. 输出结果、证据、未验证部分和恢复方法，并更新当前入口。

日常可逆改动和已授权任务继续完成；不会因为每一个阶段都要写产物而额外增加一次确认。新增功能、大批资产制作或会改变产品方向的选择，给出具体结果再讨论。

## 4. 一份完整示例：连接设置页

下面是可复制的设计任务示例，本文件本身不授权执行该页面改动。

```text
任务：为现有 ESP32 项目的网页“连接与数据源”页做一轮美术改进。
目的：让用户首先看懂 Web、Hub、设备三段通路，定位离线、重连和配置应用状态。
平台：桌面浏览器和 390/320px 窄屏；鼠标、键盘、触摸均能使用。

当前基线：沿用已有连接与数据源真实接口、六套主题、状态语义与现有导航。
主要参考：
- R055：纸面字段、黑标题条、下划线，用于设置和诊断说明。
- R093：清楚的功能卡与选中边界，用于数据源条目。
- REF-U15：浅色舞台与深色信息板关系，用于连接通路和列表定位。
- REF-U05：工作台层级，用于组织高密度信息。

布局：资源工作台＋纸面设置。主要信息为真实通路、当前设备、状态原因；
操作与诊断说明靠近对应对象。主视觉退让，不强塞另一台大设备。
风格：中性壳体、深槽状态面、纸面诊断表；主题色用于当前项与主动作；
黑描边建立结构，标签和印刷索引有节制。

约束：
- 不新增未经实现的扫描、修复、音频或输入能力。
- Web 连 Hub 与设备在线分别表达。
- 已发送、设备已确认应用、失败与未知分别显示。
- 不改现有配置值、设备配色、固件或协议。
- 不新增 3D 母版与远程素材依赖。

动作：条目选择和诊断展开短促到位；重连期间可中断；
简化动效直接切换状态。背景运动不进入输入字段阅读面。

验收：
正常、无设备、离线、配置待确认、拒绝和长错误说明均能读懂；
桌面及 390/320px 无横向溢出；键盘焦点和当前项可区分；
主题切换不改变状态含义；提供实际截图和主要操作录屏。

交付：有限范围的可运行改动、参考转译表、组件状态、验证结果、
明确的未验证项和本轮备份恢复路径。
```

## 5. Agent 完成时必须回答

- 具体改变了哪个阅读或操作问题，参考中的方法怎样转译？
- 哪些是用户已确定的规则，哪些是本轮试样参数？
- 使用了哪些资产，来源、母版和当前使用状态是什么？
- 实际检查了哪些画面、状态和平台？有什么未检查？
- 装饰动画是否改变数据含义，是否能暂停和简化？
- 如何恢复这轮改动？下一步是否确实需要用户选择？

## 6. 失败时的纠偏指令

| 用户反馈 | 首先检查 | 修正方向 |
| --- | --- | --- |
| 像普通后台 | 字号层级、主焦点、外壳与凹槽是否同质 | 先重做构图与容器家族，再补纹理 |
| 没有绝区零味 | 大字裁切、器物轮廓、印刷与交互形状是否共同成立 | 选具体参考做同内容对照，不堆贴纸 |
| 太花、太吵 | 色面数量、背景对比、常驻动作面积 | 减少同时竞争的层，保留一处主色面 |
| 太空 | 被标题、状态与无用留白占据的面积 | 合并次级信息，让主读数和器物获得有效空间 |
| 字体不对／重合 | 中文字形、实际墨迹、单位与边界 | 先量字形，补缺字和紧凑规则，再调整字号 |
| 器物像假的 | 用途、分件、枢轴、厚度、贴花透视和材质 | 回母版修结构与印刷，避免表面加细节掩盖 |
| 动起来没感觉 | 是否有明确触发、主次、加减速与落点 | 选一个流程调整时序，加入功能明确的主体联动 |
| 卡顿／闪烁 | 绘制面积、资源读取、缓存、分辨率、离屏行为 | 用测量定位瓶颈，减少无效刷新并保留回退 |

先指出原因与依据，再完成可验证的修正。不要用“已经很像了”的判断替代用户看到的实际问题。
